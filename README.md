ip란?
: 인터넷상에 연결된 모든 기계(핸드폰, computer, nas 등) 서로를 식별하고 데이터를 통신하기 위해 사용하는 고유한 숫자값
: 한마디로 데이터를 올바른 목적지로 보내기 위한 필수적인 요소 !!

IP주소 종류
- IPv4(32 bits 주소체계 192.168.2.16 과 같은 형태로 표시)
- IPv6 : 128 비트 주소체계

분류방식 : 공인ip, 고정ip, 동적ip, 사설ip
- 공인ip : 전 세계적으로 고유하여 외부 인터넷에서 기기를 식별하는데 사용
- 고정ip : 영구적으로 할당되는 ip주소
- 동적ip : 라우터에서 일시적으로 ip주소를 할당받음. 컴퓨터 재부팅시 ip주소가 바뀔 수 있음.
- 사설ip : 사무실 혹은 가정에서 사용되는 ip

127.0.0.1의 의미
- 본인 pc에 연결된 ip주소가 있듯 localhost에도 짝지어진 ip주소가 127.0.0.1
-> 나 자신을 가리키는 주소

도메인과 ip주소의 관계 
- 웹 브라우저가 도메인과 연결되어 있는 ip주소를 찾아서 이동해줌.

DNS 란 ? Domain Name Service
: 도메인 명을 IP 주소로 변환하는 서비스 
: 네트워크에서 정보를 요청할 때마다 DNS 서버를 통해 도메일 이름과 ip 주소간의 변환작업이 이뤄짐.
: DNS는 인터넷 상에서 정보를 검색하고 서비스를 사용하는데 필수적인 기능으로 이메일, 파일 공유, 문자열 데이터 등 네트워크 서비스를 가능하게 함.

포트란 ?
: 다른 지역으로 갈 수 있는 관문과도 같은 개념
: 외부의 다른 장비와 접속하기 위한 플러그와 같은 것
: 컴퓨터의 여러 프로그램들이 실행되고 있을 때 그 중 어느 프로그램에 접속해야하는지 알려줌

- WAS(Web Application Service)라고 하며 아파치 소프트웨어 재단의 
애플리케이션 서버로서 자바 서블릿을 실행하고 JSP가 포함된 웹 페이지를

JSP란?
- html코드에 자바 코드를 삽입하여 서버에서 동적으로 웹페이지를 생성하는 
서브 스크립팅 기술 
- 내부적으로 자바 서블릿으로 변환되어 실행된다 !! 

서블릿이란?
- 자바를 사용하여 웹을 만들기 위한 기술 
- 클라이언트가 어떠한 요청을 하면 그에 대한 결과를 다시 전송해야 하는데 
이러한 역할을 서블릿이 한다 
- 요청을 전송받은 서블릿 컨테이너는 HttpServletRequest, HttpServletResponse  객체를 생성한다 
- web.xml을 기반으로 사용자가 요청한 URL이 어느 서블릿에 대한 요청인지를 찾는다
- GET요청이냐 POST요청이냐에 따라서 doGet() 혹은 doPost()를 호출한다 
- doGet() doPost() 메소드가 동적인 웹페이지를 생성후 HttpServletResponse
객체에 응답을 보냄 

GET
- url에 파라메타를 포함시킴

POST
- url에 파라메타를 포함시키지 않음 즉 url에 노출시키지 않고 
서버에 요청한다 

WAS와 웹 서버 차이 
WAS
- 동적인 콘텐츠(장바구니, 주문, 로그인, 회원가입) 
를 처리하고 제공하는 서버를 뜻함 

웹서버
- 정적인 콘텐츠를 제공하는 서버 
정적인 콘텐츠란? html, css, js, img 파일 
- http를 이용해 클라이언트에게 웹 페이지를 제공 


톰캣 디렉토리 구조
bin : 톰캣을 실행하고 종료시키는 스크립트 파일이 들어있는곳 

conf : 서버 전체 설정파일 폴더 
server.xml => 톰켓의 주 설정파일(도메인, 포트)등 접속에 
관한 설정이 주를 이룬다 
context.xml => 세션, 쿠키 저장 경로 등을 지정하는 설정파일
web.xml => 톰캣 환경설정 파일 한글 인코딩 필터 등 

lib : 톰캣구동하는데 필요한 라이브러리(jar)가 들어있다 

logs : 예외 발생 시 로그 저장 

webapps : 웹 애플리케이션 폴더 

temp : 임시 저장용 폴더
work : jsp 파일을 서블릿형태로 변환한 java 파일과 class 파일이 저장

systemctl
- 리눅스 시스템에서 systemd 시스템 및 서비스 관리자를 제어하는데 사용한다.
또한 systemctl은 서비스 시작, 중지, 재시작, 활성화, 비활성화 등을 관리한다. 
- 시스템 상태를 확인하고 부팅 시 서비스 자동실행을 설정함 

명령종류
start : 서비스 시작
stop : 서비스 중지
status : 서비스 상태 확인 
restart : 서비스 재시작 
reload : 서비스를 중지하지 않고 설정 값을 반영
enable : 시스템이 재부팅하면 자동으로 서비스를 실행하도록 등록 
disable : enable 한 서비스 해제

jar vs. war 
: jar 이던, war 이던 자바 애플리케이션 빌드 산출물이라고 보면됨

jar (Java Archive)
- 라이브러리 모듈 등을 하나의 파일로 묶어서 배포
- Class(리소스, 속성), 라이브러리 파일을 포함
- jar가 되는 조건 -> 반드시 main 메소드를 포함하여야 함
- springboot는 톰캣을 내장하고 있고 main 메소드가 존재하기에 jar 파일로 배포해도 상관은 없음
- 단, 전자정부프레임워크, 스프링 레거시, Maven 프로젝트, 다이나믹 웹 프로젝트 등은 jar로 배포 시 오류가 남
- 장점) jvm에서 직접 실행하기에 별도의 was(톰캣, 웹스피어)가 필요하지 않음
- 단점) jsp나 서블릿 컨테이너에 대한 표준 기능을 사용하기 힘듦
       스프링부터에서 화면단을 머스테치나 타임리프 등을 사용하지 않고 jsp로 구현을 하였다면 배포해야 함
  
war (Web Application Archive)
- 웹 애플리케이션을 패키징하고 배포하는 역할
- WEB-INF, META-INF, 등의 표준 웹 디렉토리 구조를 가짐 (web.xml)
- 웹 애플리케이션 배포를 위한 특수한 jar 파일이라고 보면됨
- main 메소드 없어도 됨
- 웹 컨테이너를 통해 애플리케이션을 실행하므로 다양한 웹 기능과 서버 환경을 사용할 수 있음
- was(톰캣, 웹 스피어)에 종속적이기 때문에 특정 웹 컨테이너 환경이 필요함


Maven 과 Gradle
: 모두 빌드 도구임
빌드란 : 소스코드를 컴퓨터에서 실행할 수 있는 독립적인 형태로 변환하는 과정

Maven
- 설정에 있어서 xml 형식으로 관리
- 대형 프로젝트에서 빌드 속도가 느림

Gradle
- Groovy 기반으로 스크립트 형식으로 관리
- Maven보다 빌드 속도가 빠름(100배이상), 안드로이드 공식 빌드 도구

웹 서버를 사용하는 이유
1. was의 부담을 줄여주기 위해 사용한다.
2. 보안기능을 제공한다.
   -> 웹서버는 웹 페이지에 대한 접근을 제어할 수 있다.
   -> SSL/TLS 프로토콜을 사용해서 데이터를 암호화하고 엑세스 제어 방화벽등의 보안 기능을 제공하여 웹 사이트를 보호한다.
3. 웹 서버는 대부분 비동기 처리 방식을 사용하여 높은 성능을 제공한다.
   -> Apache, Nginx 등의 웹 서버는 이벤트 기반, 멀티 프로세싱, 스레드 풀 등의 기술을 사용하여 수천 대의 클리이언트로 요청을 동시에 처리 가능하다.

프록시란(froxy)?
: 대리자라는 사전적인 뜻을 가짐
- 서버와 서버사이의 중재자 역할을 함
- 프록시를 쓰는 이유 : 보안상의 이유로 직접 통신할 수 없는 두 지점사이의 대리로 통신을 수행하도록 함

프록시의 두 종류 (리버스 프록시, 포워드 프록시)
- 프록시 서버는 어느 방향으로 데이터를 제공하느냐에 따라 구분함

- 포워드 프록시 : 학교, 기업체 등과 같은 기과에서 해당 기관에 속한 사람들이 제한적인 인터넷 사용을 위해 방화벽을 사용하는데 포워드 프록시 서버는 방화벽과 같은 개념으로 제한을 하기 위해 사용됨. + 특정 사이트에 접속하는 것을 막을 수 있음(룰을 추가해야함)

- 리버스 프록시 : was 앞에 놓여 있는 것.
  클라이언트가 서버에 접근할 때 웹 서버에 요청하는 것이 아닌 프록시로 요청을 하고 프록시가 서버로부터 데이터를 가져오는 방식
  클라이언트쪽으로 데이터를 response 하는게 포워드라면 서버쪽으로 request를 하는게 리버스 프록시

/ect/nginx/sites/available/default

location / { => 모든 요청
                # First attempt to serve request as file, then
                # as directory, then fall back to displaying a 404.
                proxy_pass http://192.168.189.128:8080; => 클라이언트의 요청을 전달할 백엔드 서버를 명시
                proxy_set_header Host $host; => 클라이언트가 요청한 도메인 이름 전달
                proxy_set_header X-Real-IP $remote_addr; => 클라이언트가 타고 들어온 ip주소(실제 클라이언트 ip)
                proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
                proxy_set_header X-Forwarded-Proto $scheme; => http 요청인지 https요청인지 알려줌
        }

java:comp/env

- 네임스페이스의 표준 시작점 즉, 톰캣이 관리하는 리소스에 접근하는 공식 경로임

서버 스케일링이란?
- 트래픽이 많다는 것은 사용자 접속이 많아서 전송하는 데이터의 양이 많다라는 뜻
- 즉, 동시접속자가 증가하게 되면 서버가 부하가 생긴다 -> 한꺼번에 많은 트래픽 요청을 받으면 서버가 과부하 걸려서 다운되게 됨
=> 서버 스케일링이란 서버의 부하를 줄이기 위해 서버의 개수를 늘리거나(스케일아웃) 서버의 성능을 높이는 행위(스케일업)

1. 스케일 아웃(Scale-out)
- 서버를 여러대로 추가하는 방식
- 서버를 추가로 확장하기 때문에 수평 스케일링이라고 함
- 서버가 여러대가 되기 때문에 각 서버에 걸리는 부하를 균등하게 처리하는 로드밸런싱이 필수임
- 장점) 여러대에서 분산 처리를 하기에 한 서버가 장애를 일으키더라도 다른 서버로 서비스 가능
- 단점) 관리가 어려움, 모든 서버가 동일한 데이터를 가지고 있어야 함. 파일동기화 같은 문제가 발생할 여지가 있다.

2. 스케일 업(Scale-up)
- 해당 서버의 성능을 높이는 방법, CPU, 메모리의 성능을 높여서 더 많은 요청에 대응할 수 있도록 함
- 하드웨어 그 자체의 성능을 높히는거라 수직 스케일링이라고 함
- CPU나 RAM을 추가하려면 현재 서버에 추가 부품을 장착할 수 있는 여유 슬록이 있어야 하며 그게 아니라면 서버 자체를 고성능으로 교체해야 함
- 장점) 관리 편함 (서버 하나만 강화하면 되므로 여러 서버 간 동기화, 네트워크 구성, 로드밸런싱 같은 복잡한 설정이 필요없음)
- 단점) 급격하게 처리량이 많아지는 경우 서버 한 대에 모든 부하가 집중되므로 장애 시 큰 영향을 받을 수 있음, 성능 증가에 따라 비용이 많이 들 수 있음

로드밸런서(Load Balancer)
- 로드밸런싱과 로드밸런서의 차이는 로드밸런싱은 여러 서버에 네트워크 트래픽을 분산하는 기술이며 로드밸런서란 그 트래픽 분산 작업을 수행하는 하드웨어나 소프트웨어 장치
- 로드밸런서는 네트워크 트래픽과 클라이언트의 요청을 여러 서버에 적절히 분배시키고 서비스를 무중단으로 추가하거나 뺄 수 있음====================================================================================

로드밸런서의 종류
1. L4 Load Balancer
- OSI 7계층에서 4계층인 전송 계층을 기반으로 해서 포트 번호를 바탕으로 부하를 분산시키는 로드밸런서를 L4 로드밸런서라고 함
- 4계층 이하의 모든 정보를 갖고 있기 때문에 ip주소와 포트 번호 등을 로드밸런싱의 데이터로 활용함
- 한 대의 서버가 각각 다른 포트 번호를 부여하여 다수의 서버를 운영하고 있다면 최소 L4 이상의 로드밸런서를 사용해야 함

2. L7 Load Balancer
- OSI 7계층에서 7계층인 HTTP 헤더, 쿠키와 같은 사용자의 요청 정보를 기준으로 특정 서버에 대해 부하를 분산시키는 로드밸런서를 L7 로드밸런서라고 함

로드밸런싱 알고리즘 종류
1. 라운드 로빈
: 로드밸런싱에서 가장 많이 사용되는 알고리즘으로 클라이언트의 요청을 여러 대의 서버에 순차적으로 분배하는 방식
: 모든 서버의 스펙이 동일하거나 비슷한 경우에 사요할 수 있는 알고리즘

2. 가중 라운드 로빈
: 각 서버마다 가중치를 설정한 후 가중치가 높은 서버로부터 클라이언트의 요청을 우선적으로 전달하는 방식
: 주로 서버의 트래픽 처리량이 다른 경우 특정 서버의 스펙이 더 좋을 경우 가중 라운드 로빈 알고리즘을 사용하면됨
